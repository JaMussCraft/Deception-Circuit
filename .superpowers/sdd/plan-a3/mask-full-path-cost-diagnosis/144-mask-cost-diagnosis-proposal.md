## How verified

Source inspection distinguishes cold compilation, repeated source refresh, repeated authority checks and native model work. The full successful production mask pilot cadence already includes every callback site: initial entries, both objective arms, all task entries, complete H-bank collection and all crossed/utility operation groups. Native targets, update/backward, full validation/replay/positive controls, parity, checkpoint and restore/export work remain additional mandatory phases. Logical inventory keys do not count physical forwards or scheduler calls. [Exact cadence](/projects/beto/swong2/Alignment/Deception-Circuit/.claude/worktrees/specificity-ladder/docs/research/specificity-ladder/reports/142-real-input-readiness-evidence/cadence.json)

The proposed CPU driver measures these disjoint components:

- Read and validate the genuine original upper pilot inventory; construct its actual key-hash proof; validate its static allocation contract against the original source. Read original admission/reservation bytes and verify their actual binding.
- Time the real immutable successor-chain reader and actual canonical ledger normalization. No copied ledger is substituted. Unknown reservations or changed live facts refuse; optional normalization refusals are retained explicitly, with an already-expired refresh deadline preventing an open wait. A refusal is not recorded as valid-path timing.
- Construct the low-level original authority file witness using genuine reservation/admission/inventory/origin-snapshot and actual chain roots, preserving duplicate file occurrences; time fresh byte-witness checks separately. Measure real recursive inventory freezing and retained-proof walking. Do not instantiate a private authority context directly or present this standalone witness as authority.
- Read, completely validate and recursively freeze the genuine repaired full target key proof exactly as used before model access. Record wall/CPU time and observed peak host memory. This is a cold proof component, not a repeated-guard multiplier.
- Time actual serial `scontrol -o show job $SLURM_JOB_ID` queries in this real CPU allocation and retain the raw records. They describe CPU scheduler RPC latency only. Do not feed them through a fake H200 adapter or claim GPU parser/lease admission succeeded.

The driver never calls `validate_reservation(require_allocation=False)`, never supplies an allocation reader/test adapter, never toggles `injected`, never mints `_AuthorityContext`, never disables a guard and never loads a model. Real normalization failure does not prevent independent static components from being measured, but prevents calling their combination a successful current-authority path. ## What is NOT done

A fully valid production `make_authority_context` and repeated `validate_reservation` path cannot be measured successfully on this CPU job. The actual allocation must satisfy the frozen mask hardware, source checkout, exact job/reservation identity, current mapped ledger, admission and lease requirements. No preserved prior record supplies a current lease, and the old reservation cannot be reassigned to the repaired source.

If that remaining full live-authority measurement proves indispensable, the minimum legitimate diagnostic contract is a **new** root-bound single-H200 allocation, with the exact immutable repaired scheduler checkout/source, separate reserved output, real job ID, original validated pilot upper inventory and independently adequate host/disk capacities. The concrete conservative resource contract is `gpus=1`, `gpu_type=h200`, `cpus=4`, `memory_bytes=68719476736` with a separately validated host allowance of `60129542144` bytes; both admission and reservation bind that same contract. The scheduler work directory is the final immutable runtime, while reserved output is a separate new directory. The existing finish reserve is `300` seconds and minimum shard is `60` seconds. A prospective `10`-minute diagnostic would retain `0.1667` GPU-hours and leave at most `240` seconds for diagnosis before those reserves; it is acceptable only if the CPU results justify that work bound. It is not claimed sufficient now, and no native model loading is included. The final source must include any approved policy amendment, with regenerated source-bound inventory and a real matching Slurm job. A short allocation is not free and cannot automatically become another replacement attempt.

The existing contingency phase cannot admit that diagnostic unchanged: a real mask-pilot inventory is M1; execution and completed-pilot intake require M1/masks; both shared and mask-specific validators enforce its cumulative share, and the original charge is retained. An extra diagnostic allocation plus a later pilot would be two new reservations, so it is outside the one-replacement proposal below unless separately authorized.
