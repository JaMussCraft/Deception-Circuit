`path_patching.py` mentions 8×128 only in timing calibration comments/constants; its tensor patch primitives are generic. Its generic normalized_effect imposes a counterfactual-gap eligibility threshold and the old sign convention. New primary raw truth-margin effects should reuse scoring primitives, not normalized_effect or its usable filter.

Use one physical L frozen from the maximum tokenized prompt across BOTH panels (or explicitly separate fixed panel shapes, with every within-panel baseline/donor/patch on its same shape). Keep B=8 unless necessary. Right-pad with a frozen legal token; dummy rows have exactly their first attention-mask entry set to1, so readout is0, and are never scored. Assert `len(ids)==length<=L`, B capacity, paired lengths/counts and map bounds before CUDA. Physical shape changes require new baseline checksums; old 8×128 checksums are not portability targets.

## Minimal dictionary/tensor contract

- `batch_inputs`: each variant needs `ids: list[int]` and `length: int`. New implementation also validates bounds and row count.
- `assemble_path_streams`: each recipient additionally needs `truth_id`, `other_id`, `variant_id`; donors need ids/length. It takes one mapping per row; each mapping is list of `(recipient_position, donor_position)`. Sender keys are tuples such as `('head',13,20)`. Existing `scope` argument is UNUSED in assembler: maps alone determine where senders change. New adapter should preserve that explicit distinction.
- `semantic_map`: audits need `valid`, `ids`, `length`, `segments: dict[str,list[int]]`. Exact all_aligned additionally requires identical entire ids vectors. Common/readout/items require old accepted scope names. Returned map is one-to-one on both sides.
- `remap_capture`: donor value `[1,Ldonor,D]`, mapping above, requested recipient physical L; returns `[1,Lrecipient,D]` and `[Lrecipient]` bool. It checks physical tensor bounds, NOT logical donor/recipient nonpadding lengths; validate logical bounds in manifest gate.
- `score_capture`: capture must include READOUT_KEY, capture.readout and outputs; truth_ids/other_ids and optional donor_ids cover only real rows. Returns metrics `emitted_id`, `truth_margin`, `p_truth`, `p_other`, `other_mass`, fp32 checksum, top10; optional p_donor/donor_margin, plus detached fp32 logits. Prefix all row identity/factor fields separately. Do not relabel arbitrary non-item argmax as refusal.
- `Streams`: `[B,L]` recipient input_ids/attention_mask; `[B]` positions/target/distractor; clean_outputs for ALL head/MLP/embed components (all_component_keys), corrupt_outputs only selected senders after recipient fill; `[B,V]` clean/corrupt fp32 readout; `[B]` margins/gap; real-row ids and rows metadata. Corrupt outputs must stay recipient-filled outside maps. New task can set informational counterfactual metadata explicitly rather than inheriting ITEM_SWAP default.

`family_replacements(clean_outputs, donor_outputs, maps,keys,dose=1)` accepts runtime shapes, writes only mapped positions and leaves everything else free. It expects raw donor-coordinate tensors; Streams.corrupt_outputs have already been remapped and must NOT be passed as raw donor outputs. `self_replacements` masks real prefix tokens only. Numerical_receipt is finite and <=1e-5, reporting bitwise and max error; spec still requires explaining nonzero differences.

## Role alignment and receiver semantics

Old semantic_map matches shared segment NAME, equal span length and exact token-vector equality. It greedily deduplicates overlaps (readout first for common), returning sorted pairs. Thus it can be reused unchanged if new audits emit stable role names and unchanged-token spans, but it does NOT implement role aliasing or a generic fresh auditor.

Define named item roles from actual identity (`item:copper:intro`, `item:copper:record`, `item:copper:question`, `item:copper:option`, etc.). Use a stable literal mention/occurrence role when an item appears repeatedly. Never use `truthful_item`/`favored_item`/option-index as the identity key: a T/F/order flip changes those relationships. Audit matching offset-contained tokens, exact span tokens and injective identities. Frozen shared non-item roles may include task context, unchanged question/answer stem, record predicate spans and named beneficiary mention. Distinct predicates/changed clauses do not match merely because their role names match; exact token equality rejects them. Exclude stakes clause entirely from common sender mapping (even accidental identical subspans), and record omissions by role/reason. For native bridge retain old literal saved semantics and exact named-item anchors; no stretch/index copy. Overlapping broad spans need care: old intro spans include all text before designation; changed stakes/task within such a span causes the entire broad span to drop, so new audits should explicitly enumerate the prospectively intended stable roles.

Important: `run_stage2` actually calls `pp.readout_from_receivers(...,{receiver:capture.outputs[receiver]})` without a position mask. It replays the receiver at ALL positions; the pilot helper receiver_position_mask is NOT USED in that loop. Common/readout scopes describe SENDER alignment, not receiver restriction. Preserve all-position receiver semantics in the continuation unless design/spec explicitly chooses a new receiver-position estimand. K/V replacements occur before recipient-position attention computation/RoPE; donor attention matrices are never transplanted. For L17Kgroup6 affected heads are24–27; Q24 is a single query head.

## Provenance traps

1. Pilot CODE_ROOT derives from imported old module path; ROOT is hardcoded primary `Deception-Circuit`, not worktree. Its source/data/mask paths intentionally reach primary outputs. A new module must declare and hash its own code paths explicitly.
2. Pilot build_manifest fingerprints only old pilot .py/.sbatch/test files in code_sha256 and dirty_diff_hash; neither new validation files nor hooks/path_patching/readout compatibility dependencies are included. git HEAD alone misses untracked additive files. Hash new runner, prompt builder/auditor, tests, wrapper, imported old helper module, hooks.py/path_patching.py plus directly used compatibility/model-loader sources, resolved data/masks/tokenizer files and exact frozen prompt/map/grid payloads.
3. `manifest_hash` is digest(body WITHOUT manifest_hash); never hash the self-inclusive object. Keep schema version and physical B/L/scoring path/dtype/attention/software/cache revision explicit. Hashes of files record exact bytes, digest(dict) canonicalizes JSON.
4. Pilot stage1 enforces original sources + original code hashes on disk. stage2_provenance intentionally does NOT compare old source hashes to current old code: it checks parent data/tokenizer + gate and complete baseline IDs, preserves old code fingerprints and computes current old-pilot-file hashes. Neither function validates new validation source. New phase needs independent manifest/provenance and immutable old parent references, not an edited parent or a renamed old schema.
5. frozen_families outside-mask selection uses module SEED (20261020), not supplied args seed, and chooses across candidate layers, not specifically layer13. New single layer13 outside-D∪H∪F control must be selected explicitly by new frozen seed/hash and validated against mask union. Reuse FAMILIES only as a documented reference; do not call focused_grid, which expands the old receiver grid.
6. Parent baseline completion verification covers IDs/count only and hashes baseline bytes; it is not new panel validity. New gates must cover exact factorial keys/donor axis, logical answer tokens, no split/story leakage, logical map bounds and all planned cells, with attempted/completed/excluded statuses. New source exclusions must hash actual sample.json sources; old overlap field is incomplete per design audit.

## Thin additive architecture

Prefer one new `scripts/sdr_routing_validation.py` runner plus new test/wrapper files; split a prompt/audit helper only if file size warrants it. Import unchanged pilot serialization/scoring/remapping/family/no-op helpers, and low-level hooks/pp APIs. Do not refactor the evidence pilot.

New functions needed: `build_fresh_panel` / `build_native_bridge`; `audit_validation_variant` (native/fresh dispatch); `freeze_factor_donors`; `freeze_role_maps`; `freeze_validation_grid`; `build_validation_manifest` / `verify_validation_manifest`; `validation_batch_inputs(variants,device,physical_shape)`; `assemble_validation_streams` (small adaptation of old 655–680 with runtime B/L and validated maps); baseline/gate, route execution/checkpoint and paired story summary functions. Treat shape/scoring/provenance as explicit manifest contracts, with baseline-only and full-grid outputs separate and linked by hashes.

Verification before runs should use tokenization-only CPU gates and focused synthetic tensor/model tests for B/L padding, readout, role mapping under T/F/order flips, recipient fill, raw-vs-remapped donor handling, no-op full-vocabulary controls and manifest mutation rejection. Never execute notebooks. This inspection ran no inference or tests and made no code/git/job changes.
