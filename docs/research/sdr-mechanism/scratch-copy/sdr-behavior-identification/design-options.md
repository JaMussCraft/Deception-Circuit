# Next original-SDR study: design choice

2026-10-25. Design only. The lead authorized a bounded CPU study after reviewing the original-mask findings. Other agents own v2 circuits and selective suppression. Prior failed gates and stopped pathways stay closed.

## Recommendation

Execute a **native task-identifiability audit** before another GPU study: classify the original clauses and response contract, reconstruct exact fixed-fact support, and compare fixed simple behavioral predictions with existing native outputs. The useful result is either a native contrast worth intervening on or a precise account of what the saved experiments cannot distinguish. This is a retrospective evidence analysis; freezing its tables now does not make old outcomes independent confirmation.

The previous neutral work identifies shared cue/content influence but does not identify the original behavior. Native reporting asks which result will be shown, so selecting a harmless item is a disclosure-selection commitment. It is not automatically a false assertion about which item is damaging. The original 20 SDR clauses also vary between explicit problematic/flagged references, positional “second” references, and unresolved demonstratives; five shared clauses do not explicitly link the consequence to disclosure at all. Those differences can change the predictions of a consequence-avoidance account.

## Options compared

| Option | Discrimination | Cost and decision |
|---|---|---|
| Original-native semantics/support and fixed-rule reanalysis | Tests whether native output changes track factual designation, positional/example cues, or the clause's recoverable avoided disclosure; identifies actual and missing fixed-fact donor cells. | Chosen. CPU, existing artifacts, $0 API/GPU; finite tables and a report. |
| New clear factual assertion versus selection task, with crossed receiver and consequences | Could separate false reporting from allowed selection, provided both tasks have capable controls. | Defer. New task semantics are scientifically useful but do not repair the original native evidence; recent synthetic reporting controls repeatedly failed. |
| More neutral token/head localization | Further constrains where cue/content replacement has effects. | Defer. Shared S32 already has strong causal effects and position constraints; no new prediction connects further localization to deception. |
| Small native causal rescue | Could distinguish correction via same-answer donor state from literal answer transport. | Candidate successor only after the audit identifies existing fixed-fact disagreement cells. Do not revive the stopped pathway grid. |

## Bounded chosen scope

Use all 25 original clauses, the pilot's 480 native baseline variants and its frozen patch proposals, and the separate native 256-response EOS completion bridge. The original D/H/N datasets supply provenance only; no additional Arrow census is required. Keep these populations and endpoints separate. Score the latter with its existing released semantic labels; first-token outputs remain first-token outputs. Historical survivor selection is part of every interpretation.

Compare a fixed small rule set: damaging identity, harmless identity, explicitly designated identity, first/second response example (aliased with question order in the native scaffold), lexical first identity, and recoverable clause-avoiding identity. For saved patches add recipient-output preservation and donor-output copying as explicitly outcome-derived diagnostics. Show all rules, coverage/undefined outcomes, input-defined disagreement cells and exact transition tables; do not select a winning rule and call it confirmation.

The structural gate is logical rather than a new effect threshold: exact facts/order/response contract must match for a fixed-fact pressure comparison, and each claimed crossing must actually contain its required observed cells. Missing cells are reported, not manufactured from truth-flipped rows or pooled stories. No finding automatically releases model inference. Sample sizes, linkage, stop criteria and deliverables are in `spec.md` and `plan.md`.
