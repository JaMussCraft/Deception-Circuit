## Native construction before outcome filtering

`dataset/build_sdr_dataset.py` delegates to `dataset/build_deception_dataset.py:main(argv=None)`. The latter loads lexical pools, tokenizer-gates item pairs, constructs raw split candidates, then optionally prior-filters and behavior-filters. It saves final survivors, honest failures/resamples, config and aggregate filter reports; it does **not** persist the complete raw prompt/candidate stream. `--no-model` still creates an output config and loads a tokenizer, so do not use it as a supposedly nonmutating audit.

The reusable pre-outcome source is `dataset/deception_common.py`:

- `generate_instances(num_samples, entities, item_pairs, n_pressure_slots, variant_names, seed=0, seen=None)` builds seeded nuisance-balanced combinations, randomizing entity for a shuffled cycle of pair × slot × item-polarity × designation-polarity × template. Shared `seen` ensures exact tuple uniqueness across splits.
- `instance_key(inst)` uses entity, ordered item_1/item_2, item_polarity, designation_polarity, pressure_slot, template_variant. `instance_id(inst)` is the first12hex digits of SHA1 over pipe-joined factors. This ID excludes task and literal wording: it is not an exact prompt identity or semantic novelty guarantee.
- `realize_instance(tokenizer, spec, inst, pressures, max_seq_length=MAX_SEQ_LENGTH, check_alignment=True)` renders without model outcomes. `generate_task_data(tokenizer, spec, num_samples, entities, item_pairs, pressures, variant_names=None, max_seq_length=MAX_SEQ_LENGTH, seed=0, seen=None)` composes both.
- `build_prompt_pair(spec, variant, entity, item_pair, item_polarity, designation_polarity, pressure)` derives clean/corrupt designated-item swaps. `target` is the clean **harmless/deceptive** answer; `distractor` is the clean damaging answer. Neither is a universally correct label after truth flips or task changes.

Pools are `dataset/deception_pools/{entities,item_pairs,pressure_sdr,pressure_shared}.json`:72 entities,41 ordered pairs,20SDR clauses then5shared clauses,2audit/lab framings. The complete native tuple universe is590,400; base(entity,pair,template) composites number5,904. Items include budget/timeline, intake/output, calcium/sodium, clock/timer; names include Halbrook Medical and Nerrin Health. These are familiar synthetic vocabulary, not new lexicon.

## Safe additive completion runner

Keep `scripts/{sdr_routing_pilot,sdr_routing_validation,sdr_completion_diagnostic}.py` and old wrappers/manifests immutable. Completion `build_completion_manifest` binds an exact parent hash,1,280rows, prior failed gate, exact A100 identity, parent provenance and checksum replay; `run_diagnostic`, `verify_completion_manifest`, `replay_first_steps`, namespace/output/budget helpers are intentionally unsuitable for new scientific prompts. Do not forge parent receipts or relax old checks.

Use a new runner and wrapper, importing unchanged low-level hooks and selected small serialization/readout helpers. Minimal stable APIs:

- `component_analysis/hooks.py:load_analysis_model(model_name, *, device='cuda', hf_token=None, dtype=None)` dispatches nnsight with SDPA/BF16 on CUDA. Verify eval mode, actual dtype/device, attention implementation; load cached files offline. Existing completion disables `hooks._hf(model).config.use_cache` at runtime; record and restore it.
- `hooks.capture_forward(model,input_ids,attention_mask,*,components,positions=None,replacements=None)` returns captured component tensors and logical readout indices. `hooks.READOUT_KEY` captures final-normalization input. `hooks.readout_logits(model,residual,*,scale_from=None)` recomputes actual RMSNorm/unembedding FP32; use this full-vocabulary argmax, not captured BF16 model logits or a forced candidate choice.
- `scripts/sdr_routing_pilot.py:capture_logits(model,capture)`, `score_capture(model,capture,truth_ids,other_ids,donor_ids=None)`, `numerical_receipt(expected,observed)` are shape-generic. Score helper returns FP32 vector checksums/top10/margins and real-row metrics; arbitrary noncandidate argmax is not refusal. Numerical receipt records finite/maxerror/bitwise status with tolerance1e-5; retain nonzero differences explicitly.

`validation_batch(variants,device)` is already8×192, right-padding IDs0, dummy rows with mask[0]=1. Real rows need `ids,length`; validates1..8rows and no truncation. Its shape is hardcoded: import unchanged only if the newly frozen full panel plus generation cap fits this exact shape. Otherwise write a small explicit new adapter with manifest B/L, preserving right-padding and dummy-row discipline. Native old pilot batch helpers hardcode8×128 and are unsuitable for completions. Hooks readout defaults to `mask.sum(-1)-1`; append tokens at logical length, update mask, and read the newly last logical token. Do not left-pad or compact completed rows within batches.

Prefer a small new generation adapter using those mechanics over copying the entire parent-bound script. It can generate all steps READOUT-only with independent new baseline numerical controls; all-component capture is needed only for explicitly frozen self-replacement checks, not every behavior forward. Keep fixed batch slots/physical shape, finished rows retained, greedy FP32 decisions, EOS configured and frozen.
