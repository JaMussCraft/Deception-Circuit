The core fails six of seven declared criteria; those criteria overlap and are not six independent statistical tests. The clearest conclusion is that this shared core does **not** outperform its fixed matched random comparator on this instructed-lying development slice under zero ablation. ## Mechanistic interpretation

The random support removes instructed false reporting while leaving most ordinary truthful answers usable. This is compatible with disruption of the ability or willingness to follow the lying instruction, a shift toward default truthful responding, or other task/policy effects. It does not by itself identify a deception-specific mechanism; H asks for behavior that can remain correct even if following non-default instructions is impaired. Thus matched factual H utility is necessary here but insufficient to rule out general instruction-use or answer-transformation effects.

Likewise, the core's effects on D and H do not show that its members are a pure formatting circuit. F membership was not manipulated in this contrast. Zero replacement can create unnatural activations; these results do not settle the interpretation of historical interchange knockouts or donor-content dependence. The task is explicitly instructed lying, not incentive-driven strategic deception. Neither this negative core result nor the striking random result refutes every possible selective submask or validates a publishable internal-deception claim.

The useful completed output is a tested, bounded pipeline and a discriminating negative result for this proposed core advance, alongside a concrete competing explanation to test. It is not merely another prompt-feasibility failure: the behavior and matched H control existed, the interventions ran, and the comparator changed the interpretation.

## One bounded next research recommendation, not an automatic run

The next scientifically informative question is **whether the random effect disrupts benign non-default instructions as well as lying instructions**, rather than whether another mask can beat the current score. Recommend designing one transparent truth-value recoding control on the same statements: the recipient knows an explicit true/false-swapped codebook, so correct output requires reversal without misleading anyone. Preserve the existing natural-language response interface and avoid assistant prefills. Freeze one exact template and its semantics; do not search variants. This control tests recoding/instruction use, not all possible instruction-following abilities.

A concrete subsequent protocol could cross the existing D, H and this one benign recoding arm with intact, the same core and the same fixed random support: **144 completions maximum, 36,864 generated tokens at 256 each, at most 1 reserved GPU-hour, zero APIs**. This is a prospective research recommendation only; the current failed protocol does not authorize automatic advancement to it. Root can make a separate scientific freeze decision within the existing overall authorization; no new permission ritual is required for routine CPU design. A switch of the main project to instructed-lying/recoding mechanisms or a large campaign should be presented to the user as a meaningful scope decision.

Before any ablation on the new arm, require at least **12/16 intact recoding responses to implement the declared codebook correctly and usefully**, with at least one success in each truth/form stratum; the existing native D/H intact paths must reproduce their frozen baseline. These are proposed pre-output feasibility floors, not revisions of old gates. If recoding feasibility fails, stop without rewriting prompts or replacing rows. Root must verify the staged workload/runtime fits the single-hour total reservation; otherwise return a smaller or revised costed design before launch.
