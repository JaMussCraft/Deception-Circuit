# Benign truth-value recoding adapter

Implemented only `analysis/benign_recode.py` and its focused tests. Existing worktree code, the native transfer adapter, the explicit-zero adapter and their generation hooks remain unchanged. Root owns the frozen protocol, rubric, wrapper, canonical manifest, gate receipt and launches.

The adapter creates exactly 80 rows: first 32 native intact D/H reproductions, 16 intact recoding responses, 16 shared-core recoding knockouts and 16 fixed-random recoding knockouts. Native recipients remain identical to the transfer manifest. Recoding changes only the system instruction and preserves the native user turn, statement and empty assistant start. The expected encoded label is `1-correct_option`; greedy decode cap remains 256. Prior D/H knockout results are provenance dependencies, not new rows.

CLI modes are `prepare`, `dry-run` and `run`, with required `--manifest`, optional `--protocol`, and run arguments `--output-dir`, `--phase baseline|intervention`, `--gate`, and `--resume`. Both phases use the same wrapper/source and experiment output directory. Result stores live below `run/baseline` and `run/intervention`. Every store binds the complete manifest and phase-specific runtime provenance; summaries explicitly distinguish phase completion from all-80 completion. Interrupted exact resumes use the existing verified ResultStore implementation.

Baseline executes only 48 rows. All 32 native rows must match prior token IDs, EOS ID and termination exactly before the first recoding response. The same check runs on resumed baseline records and before interventions. Runtime hardware, CUDA, package versions, Python version and all model-file hashes must equal the original transfer run. No tolerance relaxation is supported. Interventions execute only the final 32 rows, using the unchanged fixed-zero `generate_row` with its explicit ZeroHook and open MLP gates.

The root gate is a JSON object binding `manifest_hash`, `protocol_sha256`, `baseline_run_sha256`, `baseline_results_sha256`, `annotation_path`, and `annotation_sha256`. Annotation content is a JSON list of exactly 16 objects with the intact recoding `row_id`, `category`, boolean `uncertain`, and list-of-string `flags`. Extra root provenance metadata is allowed. The adapter computes success from `category == correct_encoded_judgment`, uncertainty false, and baseline payload neither empty nor capped; incidental flags do not add an undeclared veto. It requires at least 12 successes and at least one success in each source truth stratum. It does not trust a receipt pass boolean or precomputed counts. Baseline result records are independently checked for complete coverage, row content, fingerprints and result hashes. This gate affects recoding knockouts only; sparse training remains independent.

Source bindings include this adapter, the wrapper, both unchanged predecessor adapters/wrappers and the original worktree helper modules. Input bindings include the canonical protocol/rubric and all root-frozen native and fixed-zero provenance dependencies. Preparation and dry-run reject changed source, prior inputs, protocol, masks, tokenizer metadata or derived row content.

The set includes 17 new adapter cases plus unchanged native-transfer and fixed-zero tests, including the tiny-model explicit-zero comparison. Tests cover 80-row identity/code inversion, the pre-recoding 32-row identity barrier (tokens/EOS/termination), 48-row baseline ceiling, 32-row intervention ceiling, missing gate, actual annotation IDs/counts/strata/uncertainty/caps, benign flag tolerance, source/prior mutations, and real ResultStore exact resume/corruption handling.
