The suggested resource expression is conceptually suitable on a partition permitting it: `--nodes=1-2 --ntasks=2 --gpus-per-task=1 --cpus-per-task=1` requests two task GPUs while allowing one or two hosts. Official Slurm documentation supports node ranges and requires explicit task count for GPUs per task; partition limits take precedence. `--mem-per-cpu=64G` is conditional on MaxMemPerCPU and CPU-allocation rounding: Slurm can increase CPUs per task when that limit is exceeded, and core allocation may increase allocated CPUs. `--mem-per-gpu=64G` more directly expresses this diagnostic's64GiB host-memory requirement per fit. Memory options must not be combined. These are documentation conclusions, not a locally executable multinode proposal. [Official sbatch options](https://slurm.schedmd.com/sbatch.html)

For independent steps, explicit `--nodes=1 --ntasks=1 --cpus-per-task=1 --gpus-per-task=1 --gpus=1 --mem=64G --exact --exclusive` expresses the intended single-host, single-GPU fit. Official documentation explains that step `--exact` restricts requested resources and that step `--exclusive` implies exact behavior. Explicit step node count also avoids inheriting an allocation-wide multinode requirement. Steps must not use `--overlap`. `SLURM_GPUS_ON_NODE` is node-local, so a value1 on the batch host cannot prove or disprove a global two-GPU allocation. [Official srun options](https://slurm.schedmd.com/srun.html)
