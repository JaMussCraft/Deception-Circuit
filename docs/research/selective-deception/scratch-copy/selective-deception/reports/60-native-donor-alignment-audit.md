# Native donor alignment audit

Read-only source audit, 2026-10-19. No model loads, GPU, jobs, network, tests, or implementation changes. Source references below are relative to `Deception-Circuit/` unless explicitly marked old worktree. Training implementation in `selective-wikitext` was not edited. Report 58 remains the scientific constraint.

## Decision

**The current native runner cannot evaluate different-length native recipients against a nonself native H donor correctly by adding padding at the caller. There is no supported independent donor attention-mask/position interface.** Passing `corrupted_attention_mask` today silently loses the argument in dual-stream `**kwargs`. Historical EVAL 5 packing is explicit truncation/tiling, not a valid unchanged native-prompt solution.

There is, however, an existing narrow reference-replacement hook that could support a new, reviewed **donor activation replay adapter** without changing the model forward API or training code. This requires implementation and tests, and a frozen activation-position/EOS policy. It is a proposal, not existing supported native functionality. Root should choose/review it before primary native assessment. Sparse training need not wait.

## Source evidence

- `models/llama_node.py:551-566`: top-level forward exposes one `attention_mask`, one `position_ids`, one `cache_position`, two token inputs, and two caches. The dual branch does not forward arbitrary kwargs into layer attention (`:767-775`).
- `models/llama_node.py:247-249`: donor attention receives a copy of clean attention kwargs, changing only `past_key_values`. Decoder attention kwargs contain one causal mask/rotary embedding/cache position (`:422-428`).
- `models/llama_node.py:652-660`: different clean/donor cache lengths are explicitly rejected because positions and rotary embeddings are shared. `:715-722` constructs one causal mask; `:756-757` constructs one rotary embedding pair.
- `models/llama_node.py:251-263`: donor attention is reshaped using the clean sequence length and mixed elementwise at the same token index. Thus independent padding masks alone would still be insufficient: a real clean prompt token could import an activation at a donor pad query. Pad query activations are not semantically valid native donor positions even if their output is finite.
- `evaluation/gen_engine.py:133-174`: generation accepts one attention mask and optional one position-ID tensor; donor token width must cover clean prompt width plus decode cap. `:202-207` derives real token positions from that single mask.
- `evaluation/gen_engine.py:247-286`: separate cache objects already exist, but prefill uses equal-width clean/donor tensors, positions are shared, donor advances by one predetermined token each step, and one mask grows with all-one columns. This does not handle donor EOS by independently masking subsequent donor keys.
- `evaluation/gen_engine.py:185-197`: uncached padded generation is explicitly unsupported because the manual mask can produce NaN. Do not relax this guard. `models/llama_node.py:728-751` is the underlying manual path.
- Old `selective-mask-pilot/evaluation/selective_runner.py:185-195` explicitly rejects unequal token lengths or unequal masks. `:233-248` uses historical `pack_reference`; `:251-265` delegates to the shared-mask generation API. `:284-287,305-310` additionally assumes SDR donor token labels, which must not be reused for native annotations.

## Historical EVAL 5 is not an escape hatch

`evaluation/benchmark_eval.py:51-65` documents honest twins for native instructed-deception and deranged pools otherwise. This describes identity selection, not independent attention/position semantics. `:220-238` concatenates partner prompt and response, truncates to requested length, and repeats only the response when short (or prompt when response empty). `:241-260` places this packed sequence into exactly the recipient's nonpad footprint because the model has one shared mask. With different native prompt lengths, donor response tokens can already occupy recipient prompt columns or vice versa. This may be a documented historical intervention, but it does not preserve both prompts and synchronize their assistant continuation boundaries as required by report 58. Do not use it unchanged or label it native aligned interchange.

## Smallest plausible adapter: replay true donor activations

Existing seam: `models/llama_node.py:113-116,125-144` installs `hook(module, corrupted, site) -> tensor` at reference mixing points. `evaluation/ablation.py:15-19,138-175` already demonstrates collecting donor activations without changing donor propagation, and `:206-220` scopes installation/cleanup. Head references are pre-o_proj tensors `[B,S,H,D]` (`models/llama_node.py:251-263`). The collector currently computes means; an indexed replay bank is new code.

Proposed ownership: add `evaluation/native_interchange.py` and `tests/test_native_interchange.py` in the new worktree; wire only its native final-assessment runner. Keep existing generation/model APIs unchanged if practical. If explicit per-forward callback support is needed, add a narrowly scoped callback to the cached engine with a backward-compatible default; avoid counting arbitrary module callbacks as implicit decode steps.

1. Generate each exact donor intact under its own original prompt bytes, mask, cumsum-derived positions, decode fingerprint and EOS set. Capture required head-site activations during its own cached prefill and decode. A collector can run on the existing all-open dual forward with identical donor token inputs: this is a computational capture mechanism, not a self-donor intervention condition. Donor propagation is gate-independent. Capture must cover every reference site present in the model or prove all uncaptured gates stay exactly open with finite internal tensors.
2. Keep donor bank tensors per valid donor position, per layer and site. Recipient uses its own original prompt/mask/positions/cache. At gated head sites the hook returns gathered **nonself donor-bank** values of exactly the recipient query shape. No donor pad activation is ever a scientific reference. An equal-shaped internal shadow stream may satisfy the unchanged model API, but must be explicitly documented as unused computational scaffolding: all active reference values come from the nonself bank; missing-bank, mapping, shape or site entries raise immediately. If root interprets any identical shadow inputs as forbidden under the no-self-donor rule, use the direct model extension below instead; do not silently substitute recipient activations.
3. Freeze the mapping before outcomes. One concrete candidate is assistant-boundary alignment: recipient real prompt position `p` maps to donor real position `max(0, Ld-Lr+p)`. This aligns both final assistant-header tokens and repeats the donor first valid activation for any unmatched early recipient prefix; it never crops or inserts tokens into either prompt. This repetition is an explicit activation-mapping choice, not a discovered equivalence. Other mappings may be preferable; none are currently specified in code or established scientifically.
4. Decode: target generation step 0 uses the recipient last prompt query and donor last prompt activation; step `t >= 1` uses the recipient's previous generated token query and donor query on donor continuation token `y[t-1]`. Each stream's RoPE positions remain its own real prompt length plus continuation offset. A target must not accidentally use the donor *next* generated token's activation.
5. Freeze donor termination policy. A finite intact donor completion may end before the target. A candidate is holding its **last captured valid query activation** thereafter. Ordinary EOS-stopping generation does not forward the emitted EOS, so this means the query predicting EOS, not an imagined EOS query. This is explicit terminal-activation reuse, not natural donor autoregression after EOS. Do not replace it with attended EOS padding, repeated response tokens, or another donor. If this policy is not accepted, a separate continuation rule must be reviewed and costed before generation. Mark primary assessment pending until this choice is frozen.

This adapter implements the same learned mask and interchange mixing rule with a declared cross-prompt position map. It does not make mismatched donor content a neutral deletion or remove the interpretation limits in report 58.

## If true independent-stream forward is required

Minimum affected interfaces: `PrunableLlamaForCausalLM.forward`, `PrunableLlamaDecoderLayer.forward`, and `PrunableLlamaAttention.forward` in `models/llama_node.py`; cached generation in `evaluation/gen_engine.py`; native caller; new tests. Add explicit donor mask/position arguments, construct donor causal masks and rotary embeddings using donor inputs/cache, propagate them through decoder attention, and retain independently correct full-key masks during decode. Do not merely invent an unsupported kwarg at the caller.

For equal physical widths with separate leftpad masks, physical cache positions can remain lockstep while real token position IDs differ. But gating still needs an explicit gather from valid donor query positions onto recipient query positions during prefill; donor-pad output cannot fill recipient real positions. Allowing genuinely different widths also requires replacing the clean-length reshape at `:251-254` and auditing every MLP/block/layer gate reference shape. The donor's own recurrent path must remain unmapped; gather only the replacement reference. After donor EOS, independently zero-masked pad keys can preserve finite computation, but pad-query activations must never become the reference: retain a reviewed terminal reference. This is larger and riskier than replay for an evaluation-only heads mask.

## Required CPU verification before primary launch

Use tiny synthetic Llama, eager and SDPA, and both supported transformers environments where existing suites require it. No tests were run in this audit.

- All-open recipient logits/generations agree with same-path intact baselines despite donor length/content changes; all outputs finite.
- Equal-length identity mapping and a fixed continuation agree with existing native dual-stream interchange, with closed/load-bearing heads. A donor change must change at least one expected reference/logit; an all-open-only check is insufficient.
- Both `Lr > Ld` and `Lr < Ld`, plus batched leftpad versus individual runs: every real recipient map indexes a valid donor activation; changes in nonattended pad IDs cannot affect real outputs. Mapping shape/bounds/site omissions fail closed.
- Captured donor activations match its own correctly positioned intact execution. Verify per-step positions and prior-token alignment, cached/teacher-forced equivalence on valid unpadded test sequences, EOS at first/early step, cap-length donor, no EOS, and target continuing beyond donor termination. Assert no post-EOS pad activation is consumed.
- Reuse fingerprint includes exact effective prompt IDs/mask/positions, model/precision/attention backend, decode/EOS policy and bank/mapping version. Same donor reused across D/H/recoding and masks must give identical bank bytes/references; changing recipient must not regenerate a donor.
- Preserve existing `tests/test_gen_engine.py` cached/uncached, corrupt-load-bearing and leftpadding regressions; `tests/test_kv_cache.py` separate-cache, mask-width and padded decode tests; `tests/test_benchmark_eval.py` historical behavior. Do not rewrite historical expectations to legitimize native misuse.

## Physical workload and reporting

Report 58 target upper bounds stay 192 completions / 49,152 target tokens for intact + three union finalists, or 336 / 86,016 for intact + six finalists, at cap 256. Reusing each of at most 16 exact donors across recipient domains and masks adds at most 16 intact donor completions / 4,096 generated donor tokens: totals at most 208 / 53,248 or 352 / 90,112. These are token/output bounds, not reserved GPU time.

Capturing during donor generation does not add completion count but adds memory/transfer/storage cost. Capturing afterward adds teacher-forced replay passes even if it adds zero new completions. Existing dual-stream recipient execution still computes an internal shadow stream, so replay does not automatically halve target compute. Bank footprint for all 32 layers x 32 heads x 128 dims in BF16 is 262,144 bytes per donor position (~125 MiB per 500-token donor; about 2 GiB for 16 such donors), before other sites/metadata. Capturing only scientifically needed heads can reduce storage but requires tests and exact finalist coverage. Measure the actual adapter workload before reserving; the 16-completion bound assumes independent donor prompt semantics and reusable execution fingerprints.

No zero replacement fallback is authorized by technical inability: zero-only native assessment is a secondary intervention and cannot establish primary efficacy of the trained interchange objective. Keep the primary native assessment technically pending until adapter/mapping/EOS policy passes review and verification.
